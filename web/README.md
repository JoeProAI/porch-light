# Porch Light Local Web

- Run `npm run build` then `npm run start`. The existing local binding is `127.0.0.1:3101`.
- Windows: run `.\Start-Local.ps1` from the repository root to launch the built web app and a duplicate-checked weather worker. The default 288 attempts span roughly a day plus network time, then stop. This isn't continuous hosting or a Windows boot service. Logs and captures remain outside Git. A page refresh only rereads the latest audited publication; it cannot refresh upstream sources by itself.
- `/` explains the product. `/operate` is the verified retrospective Manatee call sheet. `/nationwide` searches the Census county catalog and active NWS alerts, then runs `engines.national_jobs`. `/operate?county=<FIPS>` opens that nationwide run and does not substitute Manatee. `/watch` reads actual national NWS alerts. On the audited machine the radar loop is the NOAA observed GIF. On the hosted site the map uses IEM N0Q tiles, and the GIF is not proxied.
- From the repository root, `scripts/smoke-national.sh` (or `scripts/smoke-national.ps1` on Windows) runs five county source chains and prints pass/fail, timings, and gaps. It uses `engines.national_run` so it does not spend the Meterless draft budget. The web app's call sheet still goes through `engines.national_jobs`, including grounded drafts.
- Live weather on a machine with Zetaris uses local licensed Zetaris JDBC, `porchlight_postgis`, and the `porchlight_live_weather_v1` plus `porchlight_weather_captures_v1` native source views. Credentials and driver jar stay outside Git. Immutable capture reads prevent a source refresh from mismatching image bytes and timestamps.
- Hosted Storm Watch (Vercel) has no Python, no Zetaris, and no `~/.porchlight` filestore. That is why `/api/weather` and `/api/weather/radar-assets` returned 503 before the public-source fallback. No weather secret is required. The hosted path fetches `https://api.weather.gov/alerts/active` and Iowa Environmental Mesonet USCOMP N0Q tiles directly, labels the read `public_nws` / `public_iem`, and does not invent a Zetaris query id. Optional `PORCHLIGHT_WEATHER_SOURCE=zetaris` keeps the fail-closed audited path. Optional `PORCHLIGHT_WEATHER_SOURCE=public` skips the engine. Unset means: try the engine, then the public feed. Vercel sets `VERCEL=1` itself, which skips the engine. Do not add an NWS or IEM key.
- From the repository root, `python -m data.adapters.us.capture_live_weather --interval 300 --max-captures 72` runs a bounded local capture worker for about six hours. National raw data and source sidecars stay in `%USERPROFILE%/.porchlight/live-weather`, not Git.
- When Zetaris is up, Storm Watch reads through audited Zetaris SQL and serves source-hash-verified cached radar bytes. The page refreshes every minute; captures older than ten minutes are visibly stale. A refresh button on that path rereads the stored capture. On the hosted site the same button reads the public feed again. The evidence line says which path answered.
- The original animated radar loop covers the contiguous US. Night/light maps use unaltered NOAA transparent frames and official legend for available CONUS, Alaska, Hawaii, Caribbean and Guam provider regions. Census boundaries and NWS polygons share EPSG:4326 with the source images. Coverage can have gaps; blank pixels aren't proof of safety.
- Main-page sponsor roles link to actual row/model evidence. Independent resource links open public informational pages, not connected accounts or partner integrations. National weather discovery doesn't establish national care-facility ranking. No public deployment or continuous hosting is configured.
- Geographic controls use Census state/territory names, source-polygon alert fitting, cursor-centered zoom, keyboard pan and an expandable map. Radar can be hidden to read the chart. Geographic zoom doesn't increase the source radar's resolution. No satellite provider or unsourced geographic imagery is loaded.

## Nationwide Operator Workflow

- `/nationwide` reads `/api/weather` in parallel with the county catalog. Severe, extreme, and warning shapes are on the county map at load, with radar at 28% opacity under the county lines. The weather layers do not take the click. A plain click lands on the county and opens its published sheet. Shift, Command, Control, or a checkbox builds a shortlist of up to 8 counties without opening a sheet. Compare reads each published sheet. Export writes FIPS, name, state, and SAME alert names. A county is highlighted only when NWS `geocode.SAME` is a whole-county Census FIPS in that catalog. Area text is not turned into a county. Live alert model POST stays local-origin. The frozen catalog weather blob is not rewritten. The view does not pan on its own.
- `/nationwide` searches the audited 3,235-entry county catalog by name, state abbreviation or FIPS. Ambiguous names require an explicit selection. Names with diacritics can be searched without accents. The search stays below the weather list.
- County discovery and captured active-alert runs execute the national Zetaris chain. Neither substitutes the Manatee demonstration. Official alert polygons or source zone mappings determine inclusion, not place-name guesses.
- The verified call sheet appears as soon as the source chain finishes, before model processing completes. A model failure doesn't replace the ranking or hide an already verified source result.
- Unmapped alerts return an audited source gap with no facilities invented. Missing joins and excluded source rows remain explicit refusals.
- Ranked facilities can request a grounded live call script. Runtime remains Meterless plus Nemotron on the approved free NVIDIA route, with a shared 2,000-attempt cap including retries. Provider failures and budget omissions are not successful drafts.
- Call scripts show retained attempt IDs, failure reasons, the linked sole retry and available route/cost receipts. The local worker allows both bounded provider attempts to finish rather than terminating the retry at the catalog timeout. Model polling preserves the operator's selected facility.
- Use `PORCHLIGHT_ENGINE_ROOT` for the engine worktree, or run from the integrated repository with its `engines` module. Jobs and provenance-checked snapshots remain under `%USERPROFILE%/.porchlight/national/jobs`, outside Git.

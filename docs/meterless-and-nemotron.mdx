---
title: "Meterless and Nemotron"
---

Meterless is the only model path, and Nemotron is the only model family in the runtime path. Nemotron proposes joins and writes explanations. It never sets the order. A fixed formula does that (see [Ranking](/ranking)).

## Provider contract

Every model step records:

- `model_id`, for example `nvidia/nemotron-3.5-super-vl-120b-a12b`
- `mode`: `meterless/deep`, `meterless/fast` or `meterless/local`. Trace steps that use no model have `none`.
- `provider`: `local`, `nim` or `none`
- `trace_id`

## Reason

A `Reason` is Nemotron's explanation for one facility. It carries `text`, optional `rule_cites` (for example `42 CFR 494.62` with a plan section and page), `model_id`, `mode`, `provider` and `trace_id`.

## Trace

`GET /runs/{id}/trace` returns a `TraceStep` for every step: `step`, `model_id`, `mode`, `provider`, `latency_ms`, `input_tokens`, `output_tokens`, `tokens_per_sec`, `trace_id`, `started_at` and `detail`.

## Health

`GET /health` reports Meterless status (`up`, `down`, `unauthorized`, `offline` or `degraded`) along with the active provider and mode.

## Scout Intent

Exports pass through Scout Intent, which checks the request and signs an execution contract. See [Evidence trail](/evidence-trail).

<Note>Latencies and token counts in `contract/fixtures/trace_mock.json` are mock values. They are not measured.</Note>

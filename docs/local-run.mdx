[porchlight.earth](https://porchlight.earth) serves the published snapshots with no local install. Use this page when you want a fresh Zetaris chain, a captured alert run, or a new call script.

## What you need

| Piece | Expected local address | Notes |
| --- | --- | --- |
| Web app | `http://127.0.0.1:3101` | Next.js in `web/` |
| Zetaris (Docker) | UI `http://localhost:3000`, JDBC `jdbc:zetaris:lightning@localhost:10000`, REST `http://localhost:8888/api/v1.0` | Licensed local bundle. Not the managed AWS cluster |
| Meterless Nightshift | `http://127.0.0.1:8088/v1` | The NVIDIA key stays in Nightshift Providers |
| PostGIS | private read-only datasource `porchlight_postgis` | Spatial predicates stay in PostGIS |

Copy `env.example` into a gitignored env file. Names only. Never commit token values. The app reads the Nightshift proxy-token file at runtime (`%LOCALAPPDATA%\ai.meterless.runtime\proxy-token` on Windows). It does not read `NVIDIA_API_KEY` from the web env.

National captures, weather captures, and job artifacts stay outside git under `%USERPROFILE%\.porchlight`.

## Start

From the repo root on Windows, when Java 21, Zetaris, and PostGIS are already up:

```powershell
.\Start-Local.ps1
```

Or from `web/`:

```powershell
npm ci
npm run build
npm run start
```

Open `http://127.0.0.1:3101`. If Zetaris is down, nationwide jobs fail closed. They do not load Manatee in place of the county you asked for.

The Milton sheet at `/operate` renders from `web/data/manatee-ranked.json` without live credentials.

## Smoke script

On a machine with local Zetaris:

```powershell
scripts\smoke-national.ps1
```

```bash
scripts/smoke-national.sh
```

The script calls `engines.national_run` for Manatee (`12081`), Harris (`48201`), Cook (`17031`), Loving (`48301`), and one county mapped from the current audited alert. It does not spend the draft budget. If Zetaris is unreachable, it exits with that message and does not substitute a county.

A recorded local pass from 2026-10-23 is `docs/smoke-national-results.md`. Those query ids are that session. They are not the query ids on the hosted sweep snapshots.

Zetaris is the only data path for a fresh run. The web app does not query CMS, Census, SVI, or emPOWER directly. Spatial predicates stay in PostGIS. Zetaris runs the SQL and returns the audit row the sheet cites.

## What the desk shows

Hosted county files set `data_access_mode` to `zetaris`. The drawer prints query ids, the vendor query hash, the audited SQL, and the topology string:

`Separate national public-source relations in one read-only PostGIS datasource`

The datasource name in local setup is `porchlight_postgis`. The deployment used for the sweep is local Docker, not a hosted Zetaris cluster. `metadata.json` records `deployment: local-docker` and `interface: jdbc`.

The catalog read is one statement, query `833`, transaction `zetaris-national-chain`, finished successfully at `2026-10-23T20:00:50.055+00:00`. A county chain stores its own seven query ids. Match counts on those steps are SQL counts. They are not a model confidence.

## What is not claimed

A Unified Semantic Layer spread across many live physical systems is not claimed. The relations are separately projected and currently share one read-only PostGIS database.

H-MEM is not a claimed engine. The contract field `seen_before` describes an H-MEM memory of a join. The hosted drawer does not set that story. Failed joins on the national sheet are the recorded refusals (inexact geocode, missing rating, missing ZIP context, and the other rules in [Data sources](/data-sources)), with query ids, not an LLM guess.

If local Zetaris cannot be reached, a fresh job stops. The UI does not swap in another county. The hosted pack is how you read a county when you are not on that machine.
